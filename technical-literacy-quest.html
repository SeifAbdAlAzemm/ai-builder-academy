What is software?

Software is a set of instructions that tells a computer what to do. A spreadsheet formula, a browser and a mobile app are examples.

Think before building

What goes in? What must happen? What should come out? You can explain these three things without writing code.

Frontend

The screen, buttons and fields you interact with. Like a restaurant menu and dining area.

Backend

The server-side logic that processes requests and applies business rules. Like the kitchen.

Database

Organized storage for retrieving and updating records. Like a stockroom with an inventory system.

API

An agreed interface for communication between software components. Like the order-taking process connecting the dining area and kitchen.

Source code & languages

Source code is the instructions and definitions behind software. Programming languages such as JavaScript and Python express logic. HTML is markup, and CSS is a style language.

Three web layers

HTML = structure and content.
CSS = appearance and layout.
JavaScript = behavior and interaction.

Client & server

A client requests something, and a server provides a service. A browser requesting a page is a common example. Some apps also work fully offline.

Temporary vs persistent data

Temporary state disappears when a session ends. Persistent storage keeps records for later. A database can store many organized records; browser storage is another option.

Prototype & iteration

A prototype is an early version to test an idea. An iteration is one cycle of feedback, change and testing.

Bug & debugging

A bug is incorrect behavior. Debugging means finding its cause and fixing it. Test normal cases, limits and invalid input.

Find the faulty validatorREAL RULE-BASED BUG LAB

Testing before and after a change matters. A working prototype is not automatically ready for real use. Deployment is a later step; it does not fix bugs.
Instructor notes

Ask the learner to predict the empty-title result before testing. Apply the fix, then run all cases. Introduce regression testing as rechecking existing behavior after a change.
