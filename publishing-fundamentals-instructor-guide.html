MISSION 01 / 08

Beyond your laptop

Local · Preview · Production
3–4 min · CORE

هدفك

يفرق بين مكان تشغيل البرنامج والغرض من النسخة ومين مسموح له يوصل ليها.

ابدأ بالكلام ده

«لو عامل شيت على اللابتوب عندك، زمايلك مش هيشوفوه تلقائيًا. ممكن تشاركه بطريقة آمنة. البرنامج برضه، بس أحيانًا محتاج بيئة تشغيل مش مجرد رفع ملف.»

شرح المصطلحات

Local: شغال على جهازك. localhost: اسم بيشير لجهازك نفسه في الشبكة. Preview: نسخة للتجربة والمراجعة، ممكن تكون على الإنترنت. Production: بيئة الاستخدام الحقيقي. Environment: المكان والإعدادات اللي البرنامج شغال فيها. النشر لا يعني بالضرورة إتاحة عامة.

Live Demo — Access Simulator

اختار Local machine واضغط Test access from another device: إنت تقدر تستخدمه لكن الزميل مش متاح له عن بعد. اختار Private hosted preview: المدعو بس يدخل. اختار Hosted production with sign-in: المستخدم المصرح له يدخل. اختار Public hosted production: متاح للجميع. اسأله قبل كل ضغطة مين يقدر يشوفه.

مثال من شغله

أداة مراجعة عناوين تجريبية ببيانات وهمية ممكن تكون public، لكن أداة فيها بيانات شركة ومنتجات داخلية لازم تكون مقيدة حسب الصلاحيات وموافقة الشركة.

خطأ شائع

Preview مش معناها Local دائمًا. ووجود Login مش ضمان إن كل مستخدم له الصلاحيات الصح. إرسال ملف HTML محلي ممكن يكون طريقة مشاركة مناسبة لأداة بسيطة بدون نشر على الإنترنت.

Checkpoint — الإجابة المتوقعة

«عندي رابط Preview بيشتغل على جهاز زميلي، هل ده Production؟» لأ، الهدف من النسخة هو اللي بيفرق. «هل كل موقع منشور لازم يبقى public؟» لأ، ممكن يبقى خاص أو مقيد.

انتقال

«طيب لو عايز البرنامج يبقى متاح على الإنترنت، محتاج مكان يشغله.»

Find your launchpad

Hosting · Server · Cloud
3–4 min · CORE

هدفك

يختار بيئة استضافة على حسب احتياج الحل، مش على حسب اسم أداة AI اللي بنته.

ابدأ بالكلام ده

«لو فتحت محل، محتاج مكان تحط فيه البضاعة وتستقبل العملاء. Hosting هو البيئة اللي بتوفر مكان وموارد لتشغيل البرنامج أو تقديم ملفاته. Server بيقدم الخدمة، والـ Cloud يعني موارد حوسبة من مزود خدمة.»

شرح المصطلحات

Static hosting: بيقدم ملفات جاهزة زي HTML/CSS/JS، وممكن تبقى تفاعلية داخل المتصفح. Backend: معالجة على السيرفر عند الحاجة. Managed database: خدمة تخزين مزود الخدمة بيدير جزءًا من تشغيلها. Workflow runner: بيشغل الأتمتة حتى لو المتصفح مقفول، طالما بيئة التشغيل متاحة.

Live Demo — Hosting Match

في Application requirements اختار A public portfolio with images and text ثم Static web hosting. اختار Team app with shared records and private AI key ثم Backend + managed database. اختار Scheduled report that runs every morning ثم Scheduled workflow runner. جرب اختيار غلط وخليه يفسر الـ feedback.

مثال من شغله

عداد الحروف اللي بيشتغل لحظيًا على المتصفح مش محتاج قاعدة بيانات. لو الفريق بيحفظ حالة كل منتج ويشاركها، محتاج تخزين مشترك وصلاحيات. لو تقرير الساعة 9 لازم يطلع حتى لو محدش فاتح الصفحة، محتاج Runner شغال وجدولة.

خطأ شائع

Static مش معناها صفحة مفيهاش تفاعل. وAI-generated مش معناها AI-powered. مش كل مشروع محتاج Backend منفصل، ممكن المنصة تدير الخدمات المطلوبة.

Checkpoint — الإجابة المتوقعة

«أداة عد حروف شغالة بالكامل داخل المتصفح، ليه أستضيفها على Static hosting؟» لأنها محتاجة تقدم الملفات فقط، مفيش حاجة لازمة لمعالجة على السيرفر أو حفظ مشترك.

انتقال

«المكان موجود، دلوقتي الناس هتوصله إزاي؟»

MISSION 03 / 08

Give it an address

URL · Domain · DNS · HTTPS
3–4 min · CORE

هدفك

يفهم الفرق بين عنوان الموقع ومكان الاستضافة، ويعرف دور DNS وHTTPS من غير تفاصيل شبكات معقدة.

ابدأ بالكلام ده

«المحل له اسم وعنوان ومكان فعلي. الـ Domain اسم زي example.com، والـ URL العنوان الكامل لصفحة معينة، والـ Hosting المكان اللي بيقدم الخدمة. DNS زي دليل بيساعد المتصفح يوصل للمكان الصحيح.»

شرح المصطلحات

URL مثال https://example.com/tools/checker: https طريقة الاتصال، example.com اسم النطاق، /tools/checker مسار المورد. DNS بيربط الاسم بمعلومات الوصول، مش بالضرورة عنوان IP واحد. HTTPS بيشفر الاتصال وبيتحقق من هوية الخدمة بشهادة TLS؛ مش ضمان إن محتوى الموقع آمن.

Live Demo — DNS & HTTPS Simulator

اختار DNS configured + valid HTTPS واضغط Open https://tools.example.com: النتيجة 200 OK في المحاكاة. اختار DNS record missing وكرر: الطلب بيتوقف عند DNS. اختار Invalid TLS certificate: بيقف عند HTTPS. خليه يحدد فين المشكلة قبل ما تشرح. الرابط وهمي ومفيش طلب حقيقي.

مثال من شغله

ممكن ينشر أداة على رابط تمنحه المنصة، من غير شراء Domain. لو حب يعمل اسم خاص للشركة بعد الموافقة، يربط الـ DNS بالاستضافة، ويضبط الشهادة أو يخلي المزود يديرها.

خطأ شائع

شراء Domain مش هو شراء Hosting. HTTPS مش بيمنع تسريب البيانات من كود التطبيق أو سوء الصلاحيات. متعديش تحذير شهادة غير صالحة، صحح السبب الأول.

Checkpoint — الإجابة المتوقعة

«لو اشتريت Domain، هل الموقع اتنشر؟» لأ، محتاج تطبيق وبيئة تشغيل وربط الاسم. «لو الموقع عليه قفل HTTPS، هل بيانات العملاء آمنة أكيد؟» لأ، الاتصال محمي لكن التطبيق نفسه محتاج مراجعة.

انتقال

«دلوقتي لو عدلنا البرنامج والـ AI بوظ النسخة، نرجع إزاي؟»

MISSION 04 / 08

Time machine

Git · GitHub · Versions
4–5 min · CORE

هدفك

يفهم قيمة Version control، والفرق بين حفظ الكود على GitHub ونشر البرنامج.

ابدأ بالكلام ده

«لما بتعمل نسخة من شيت قبل تعديل كبير، بتعمل كده عشان تعرف ترجع. Git بيعمل حاجة منظمة أكتر للكود: تاريخ للتعديلات تقدر تراجعه وتسترجع منه نسخة.»

شرح المصطلحات

Git: نظام تتبع إصدارات. Repository: ملفات المشروع وتاريخها. Commit: تسجيل لقطة من التعديلات مع وصف. Push: إرسال الـ commits للمستودع البعيد. GitHub: منصة لاستضافة Git repositories والتعاون. Revert: تعديل جديد يعكس تغييرًا سابقًا؛ مش مسح التاريخ بالضرورة.

Live Demo — Version History Simulator

ابدأ من V1. اضغط Commit new feature: V2. اضغط Commit buggy change: V3. اضغط Restore working code: V4 جديدة سليمة؛ التاريخ القديم موجود. اضغط Push to demo repository: النسخة البعيدة تتحدث لكن Production unchanged. لو ضغط Feature بعد الـ Bug وقبل الإصلاح، مش بالضرورة يختفي الخطأ.

مثال من شغله

أداة فحص المنتجات بتشتغل، طلب من AI يضيف Export CSV، حصل Bug في الفحص. احتفظ بنسخة سليمة قبل التعديل، وسجل التعديل باسم واضح، وبعدها اختبر. لو فشل، استرجع الكود السليم واختبره.

خطأ شائع

Git مش GitHub. Push مش Deploy تلقائيًا إلا لو فيه Pipeline مهيأة. استرجاع الكود لا يسترجع البيانات ولا النسخة المنشورة تلقائيًا. لا تضع API keys أو ملفات سرية في Git حتى لو Repository خاص.

Checkpoint — الإجابة المتوقعة

«لو رفعنا الكود على GitHub هل كل الناس تقدر تستخدم الموقع؟» لأ، محتاج نشر مناسب. «لو رجعنا نسخة قديمة من الكود، هل المنتجات المحذوفة من قاعدة البيانات هترجع؟» لأ، محتاجة خطة استعادة بيانات.

انتقال

«معانا نسخة سليمة، إزاي نخليها النسخة اللي الناس بتستخدمها؟»

MISSION 05 / 08

Launch control

Build · Deploy · Verify · Rollback
5–6 min · CORE

هدفك

يميز بين نجاح تجهيز النسخة، نجاح نشرها، ونجاح تشغيلها عند المستخدم الحقيقي.

ابدأ بالكلام ده

«اعتبر إنك بتجهز وجبة للتوصيل: تجهيزها مش معناها إنها وصلت، ووصولها مش معناها إن الطلب صح. Build يجهز النسخة، Deploy يحطها في بيئة التشغيل، Verify يتأكد إنها بتعمل المطلوب فعلًا.»

شرح المصطلحات

Build: تجهيز ملفات أو حزمة تشغيل (مش كل تطبيق محتاج Build). Deploy: وضع الإصدار في بيئة التشغيل. Verify/Smoke test: فحص سريع للمسارات الأساسية بعد النشر. Staging: بيئة تجربة قبل Production. Rollback: الرجوع لإصدار سابق إذا كان متوافقًا وآمنًا. CI/CD: أتمتة خطوات البناء والاختبار والتسليم أو النشر؛ اختياري هنا.

Live Demo — Deployment Simulator

اختار Healthy V2 واضغط Run release؛ Build وDeploy وVerify ناجحين وV2 healthy. اضغط Rollback to V1 عشان تبدأ السيناريو التالي من V1. اختار Build fails ثم Run release: النسخة القديمة مستمرة. اختار Build succeeds but live check fails: V2 منشورة لكن فاشلة في الفحص. اسأله يتصرف إزاي، وبعدها Rollback to V1. وضح إن الاسترجاع نفسه يحتاج Verify.

مثال من شغله

بعد نشر Listing Checker افتح الرابط من متصفح مختلف، اختبر عنوان صحيح وعنوان فاضي، تصدير التقرير، الموبايل، والـ permissions لو فيه حسابات. لو ميزة أساسية فشلت، وقف الإطلاق أو ارجع بأمان وبعدها افحص السبب.

خطأ شائع

Build successful مش شهادة جودة. Rollback للكود مش Backup للبيانات. تغييرات Database ممكن تمنع الرجوع للإصدار القديم، فبنحتاج خطة استرجاع منفصلة. المحاكاة لا تنشر فعليًا.

Checkpoint — الإجابة المتوقعة

«الـ Build نجح والـ Deploy نجح لكن المستخدم مش قادر يحفظ. نعلن نجاح النشر؟» لأ، نوقف أو نرجع لو آمن، نصلح ونعيد الاختبار. «إيه اللي نختبره؟» الإجراءات المهمة والصلاحيات والأخطاء والبيانات.

انتقال

«مش كل نوع برنامج بيتنشر بنفس الطريقة.»

Choose your launch route

Web · Mobile · Extension · Automation
3–4 min · BONUS

هدفك

يربط نوع الحل بطريقة إتاحته للمستخدم، ويعرف إمتى الاكتفاء بأبسط طريقة توزيع.

ابدأ بالكلام ده

«الموقع بفتحه برابط، التطبيق بنزله على الموبايل، الإضافة بتركب على المتصفح، والأتمتة ممكن تشتغل في الخلفية. نوع الحل هو اللي بيحدد طريقة نشره.»

شرح المصطلحات

Web: استضافة ورابط وصلاحيات. Mobile: اختبار جهاز حقيقي، Signing وتوزيع معتمد أو متجر حسب المتطلبات. Extension: اختبار Unpacked محليًا، ثم Packaging ومراجعة الصلاحيات ومتطلبات المتجر لو هتوزعها. Automation: Runner وTrigger وCredentials وLogs. Desktop: Package أو Installer متوافق مع نظام التشغيل. PWA: تطبيق ويب بخصائص ممكن تسمح بتثبيته من المتصفح على أجهزة مدعومة.

Live Demo — Choose your distribution

في What did you build? جرّب Shared web tool → Host and share URL؛ Android / iOS mobile app → Device tests + authorized distribution؛ Chrome extension → Package extension + review / local test؛ Scheduled automation → Configure runner and schedule؛ Desktop utility → Package for target OS.

مثال من شغله

لو محتاج يراجع منتجات من الكمبيوتر والموبايل، Web App responsive ممكن تكفي. لو الأداة لازم تبقى موجودة جنب صفحة Amazon، Extension ممكن تكون أنسب بعد التحقق من سياسات الشركة والمنصة. لو محتاج تقرير دوري، Automation.

خطأ شائع

مش كل Mobile App محتاج App Store عشان تجربته. مش كل موقع responsive يبقى PWA قابلة للتثبيت. متوعدش بنشر رسمي فوري؛ المتاجر لها مراجعات وسياسات وتكاليف ممكن تتغير.

Checkpoint — الإجابة المتوقعة

«تقرير لازم يشتغل كل صباح واللابتوب مقفول، هل يكفي Web App عادية؟» لأ، محتاج بيئة تشغيل وجدولة مناسبة. «لو مجرد استخدام الأداة من الموبايل؟» ممكن رابط Web App مناسب يكفي.

انتقال

«قبل ما ننشر أي حل لازم نعرف مين يدخل، وإزاي نحمي البيانات ونحسب التكلفة.»

Security shield

Privacy · Access · Secrets · Cost
5–6 min · CORE

هدفك

يفرق بين Authentication وAuthorization، ويتجنب تسريب المفاتيح والبيانات ويفهم تكلفة التشغيل.

ابدأ بالكلام ده

«بطاقة الموظف بتثبت هو مين، لكنها مش بتديه حق يدخل كل غرفة. Authentication إثبات الهوية، Authorization تحديد المسموح له. لازم السيرفر أو الخدمة تطبق الصلاحيات، مش مجرد إخفاء زرار.»

شرح المصطلحات

API key: بيانات اعتماد لخدمة، مش كل مفتاح بنفس درجة السرية لكن المفاتيح السرية تتخزن في إعدادات سيرفر محمية أو Secret manager. Environment variable: قيمة إعداد بتوصل للتطبيق وقت التشغيل؛ لو اتضمنت في كود المتصفح مش هتبقى سرية. Privacy: استخدام البيانات بالحد الأدنى وبتصريح. Usage limit: حد للاستهلاك، مع متابعة الفواتير والتنبيهات.

Live Demo — Security Inspection

حدد فقط الاختيارات رقم 1 و3 و4: Secret API key embedded in public JavaScript؛ Customer data uploaded without approval؛ Public sharing enabled for a private team app. اضغط Flag selected risks. الاختياران 2 و5 يمثلان ضوابط أفضل وليس ضمان أمان كامل.

Live Demo — Monthly Cost

في Hosting / month ($) حط 8، AI requests / month حط 1000، Average AI cost / request ($) حط 0.02، واضغط Calculate estimate: المتوقع 28 دولار شهريًا. جرّب 2000 طلب: 48 دولار. الأرقام افتراضية وليست أسعار سوق. تكلفة AI الفعلية ممكن تعتمد على Tokens أو وحدات أخرى؛ أضف DB وBandwidth وDomain والصيانة وغيرها عند الحاجة.

مثال من شغله

متبعتش بيانات منتجات سرية أو حسابات Seller Central أو بيانات العملاء لـ AI خارجي بدون موافقة. استخدم بيانات تجريبية. لو مفتاح سري اتسرب، وقف استخدامه أو ألغِه وبدله وراجع الاستخدام والسجلات.

خطأ شائع

اشتراك ChatGPT مش بالضرورة يشمل تكلفة API. Repository خاص مش مكان مناسب لتخزين الأسرار. إخفاء زر في Frontend مش Authorization. وجود Login أو HTTPS وحده مش كفاية. Free tier مش ضمان إن التكلفة تفضل صفر.

شرح المصطلحات
